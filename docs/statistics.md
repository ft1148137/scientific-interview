# 求职统计

首页为投递统计。移除原首页与各页标语，保留必要的数据口径、来源和使用提示。

| 模块 | 展示内容 |
|---|---|
| 投递总览 | 累计投递、公司数、本周投递、进行中、明确拒绝、全库不活跃岗位 |
| 申请状态分布 | 待反馈、筛选中、面试中、Offer、明确拒绝、已撤回、流程结束、转人才库、岗位停招、状态待核验、不活跃的环状图 |
| 投递与反馈趋势 | 最近 12 周的投递和反馈双折线图，周一为一周起点；实线圆点/虚线菱形区分 |
| 公司投递分布 | 各公司投递岗位数及比例；超过 6 家时显示前 5 家与其他 |
| 方向与行业分布 | 两组条形图，各自显示数量与占比；缺分类显示“未分类” |

数字、环段、折线节点和条形均可点击查看对应岗位明细，再进入岗位详情。支持全部、近 30 天和近 90 天的投递批次；同一批次的状态和反馈使用已保存的最新记录。日期分组使用浏览器本地时区。

## 统计口径

- 一个岗位身份只计一份申请。重复提交记录、重复反馈和更换简历不增加次数；目前不区分同岗位多轮重新申请。跨网站的同一岗位仍需先核对身份，统计不会猜测合并。
- 公司按档案中的公司名称归并；别名或子公司不会自动合并。
- 最新状态按证据 `observed_at` 排序，不按后补录入的时间。排除未来时间和非法日期；同时间记录以最后录入者为准。
- `submitted` 是投递时间依据。若只有面试、拒绝等已确认状态，仍计为一份申请，但显示缺投递日期，投递趋势不补造日期。批次筛选此时使用最早已确认状态时间。
- 历史记录只确认“简历已接收”却没有投递日期时，证据使用 submission_date_unknown=true；仍计入申请与待反馈，但不会把核验日期加入投递折线。其他有明确投递日期的 submitted 记录仍正常使用。
- 只有 `unknown` 的记录不证明投递成功，不进入投递总数；已确认投递后变为 unknown 的，保留投递并归入“状态待核验”。
- 进行中包括待反馈、筛选中和面试中。Offer、拒绝、撤回、流程结束、转人才库和岗位停招单独计数；用户主动排除岗位不算企业拒绝。
- 反馈指进入筛选、面试、Offer 或明确拒绝的状态变化。同岗位同周最多计一次；重复核验同一状态不算新反馈，用户撤回不算企业反馈。流程结束、转人才库和岗位停招不推断为明确拒绝，也不纳入这四类反馈趋势。
- 统计只使用私人档案中的证据记录。不会把反馈比例解释为录用概率，也不会把未回复当拒绝。页面是数据快照，新增申请或反馈后重新生成页面。

## 方向与行业

由 AI 根据用户确认或明确资料整理，使用已有统一名称，不根据公司名称猜行业，不把搜索词直接当岗位方向：

```bash
python -m job_workbench --data data/main job-classify <岗位key> --direction '数据分析' --industry '制造业'
```

两组条形图各自使用 300px 高度的独立滚动区域，支持滚轮、拖动滚动条和键盘上下滚动；标题保持可见，分类仍按投递数从多到少排列，点击条形可查看岗位明细。

行业按企业主营业务归类；招聘主体明确为独立业务单元时按该业务单元归类。依据企业官网或已保存的业务介绍，统一分类名称，并将来源、归类理由与待核实项保存在 data/；不能因为岗位涉及 AI 就把企业归为人工智能行业。

两项都可独立更新，空字符串清除该分类；修改保留历史，后续抓取不会覆盖。旧档案缺少分类时直接显示未分类，不需要迁移。按需补分类即可，不为填满图表打断日常投递。

## 不活跃岗位

“一个月”按连续 **30 × 24 小时**定义。计时从最近一次实质变化开始：标题、公司、地点、招聘状态、JD 内容或完整性变化。首次收录从第一份岗位快照起算。再次抓取相同内容、核验、用户筛选决定、分类和申请反馈不会重置这个时间。

页面打开时根据当前时间计算，不需要新增定时任务。页面保持打开时每分钟检查阈值；岗位出现实质变化并更新页面后自动恢复。岗位列表、详情、统计明细都有标识，并可按“不活跃”筛选。旧档案使用已有变更快照计算，不重写历史。

用户也可人工标记不活跃：`job-activity <key> inactive --note '原因'`；用 `job-activity <key> auto` 恢复自动判断。人工标记保留原因、时间和历史，持续至用户撤销，不因扫描或申请反馈自动清除；不会伪造岗位变更日期。列表与详情区分“人工标记”和“30 天无变化”，统计包含两者。

不活跃是跟进标签，与在招/下线、待核验和申请状态独立。即使刚核验仍在招，连续 30 天无变化也会标记不活跃。这个规则不会自动排除、删除或判定停招。

未结束申请（待反馈、筛选中、面试中或状态待核验）被自动或人工标记不活跃后，首页从“进行中”移出，状态环图单列灰色“不活跃”；保留原申请状态，明细可同时查看。Offer、明确拒绝、已撤回、流程结束、转人才库、岗位停招继续显示各自状态；投递总数、公司/方向/行业分布和历史反馈趋势不变。环图随投递批次筛选，“不活跃岗位”总览仍统计全库。

## 分享与验证

分享岗位副本不含投递统计数据、分类、分类历史、人工不活跃标记或标记历史；只带最近实质变化时间以显示公开岗位的活跃度。私人申请信息仍留在本地完整档案。

自动化覆盖去重、证据排序、重复反馈、按周归并、批次筛选、未分类、缺日期、未知/未来记录、30 天边界、实质变化恢复，以及分类持久化与分享排除。图表计算脚本直接用于页面和 Node 测试，不使用另写的一套统计逻辑。

## 岗位标签

通过 `serve` 打开工作台，在全部岗位或岗位详情中点击“投递候选”“不感兴趣”即可保存。两者互斥，点击另一标签切换，再次点击当前标签取消；“岗位标签”下拉框支持所有标签、投递候选、不感兴趣、未决定、已投递。标签不改变企业申请状态，也不会被之后的扫描覆盖。

保存沿用 `shortlist/excluded/undecided` 字段与决定历史，并执行原档案锁、版本校验和备份。旧的候选/排除记录无需迁移。多人窗口或 AI 同时修改造成版本过期时，页面提示刷新，不覆盖新数据；保存失败不先行改变标签。

保存接口仅在本机服务中可用，需要同源请求与会话令牌；分享副本不显示标签或私人决定。直接双击打开的 HTML 是只读快照，按钮禁用并说明打开方式。

## 紧凑环状图

申请状态与公司分布都不再展示侧边标签列表。悬停或用 Tab 聚焦环段时显示名称、数量和占比；点击或按 Enter/空格进入对应岗位明细。申请状态采用固定色义：待反馈/筛选中/面试中均为黄色，明确拒绝为红色，Offer 为绿色，撤回、流程结束、停招与未知为中性色，转人才库为蓝灰色。细缝区分同色阶段。

两个小环在宽屏与趋势折线图同排，在窄屏保持两个环并列、趋势另起一行。最新验证范围见 [发布检查记录](release-readiness.md)。

![紧凑环状图与趋势同排](assets/compact-charts.jpg)

投递前的默认选择为“未决定”，岗位卡片不展示默认标签，只通过筛选查找；仍可点击候选或不感兴趣。存在已确认申请记录后，卡片只展示“已投递”，隐藏投递前标签及操作，并从候选、不感兴趣、未决定筛选中排除。详情同步隐藏操作，过往选择留在折叠历史中。只有 unknown 的记录不算已投递；已经确认投递后再进入 unknown、拒绝或撤回状态，仍不会恢复投递前标签。浏览器保存接口也会拒绝给已投递岗位设置投递前标签。
